# Contributing

Useful contributions identify a concrete weakness and preserve the benchmark's grouped evaluation. Report a synthetic sample ID, expected behavior, reproducible command and relevant code/environment. Proposed layout families should add a distinct workflow and explain how identities, pairs and derivatives stay in one split.

Do not submit real credentials, personal records, private screenshots or live service responses. Use a minimal synthetic fixture with reserved domains and deliberately invalid identity/financial formats. Do not label an AI review as human verification. Human review records must state who actually reviewed which samples and by what protocol.

Run `npm test` and `npm run verify` for code/metadata changes. Changes to generated data also need the full validation and a documented new version. Do not update the frozen generation plan merely to bypass source mismatches or tune held-out layouts after seeing results. Preserve failed QA evidence and explain repairs.

New evaluations should follow [RESEARCH_PROTOCOL.md](RESEARCH_PROTOCOL.md), declare their input access, model/version, confidence cutoff, split, and clean/stress results. Never report old v0.1 scores as v0.2 performance. Comparisons should include negative false alarms and paired context success alongside recall.

Contributed code uses MIT; contributed synthetic data, metadata and documentation use CC BY 4.0 unless an explicit compatible notice says otherwise. Retain third-party notices. No automated upload, training, export, star exchange or bulk promotional messaging is part of this contribution workflow.
